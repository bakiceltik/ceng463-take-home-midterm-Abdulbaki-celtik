\section{Question 1: Regression}

\subsection{Problem Setup}

For Question 1, I used the California Housing dataset from \texttt{sklearn}. The dataset contains 20{,}640 observations, 8 numeric predictors, and a continuous target \texttt{MedHouseVal}. I kept a single holdout test split of 20\% for the final evaluation and performed all model comparison on the remaining 16{,}512 training examples using repeated cross-validation, in line with the instruction that the test set should only be used once at the end.

Exploratory analysis showed that the target distribution was positively skewed, with training-set skewness equal to 0.9776, so I enabled a \(\log(1+y)\) transform for the main non-robust models. The strongest linear relationship with the target was median income (\(r=0.6881\)), followed by weaker associations for average rooms (\(r=0.1519\)), latitude (\(r=-0.1442\)), and house age (\(r=0.1056\)). Outlier analysis using both the IQR rule and Z-scores suggested that \texttt{AveBedrms}, \texttt{Population}, and \texttt{MedHouseVal} were the most problematic variables under the IQR criterion, with outlier rates of 6.83\%, 5.83\%, and 5.18\%, respectively.

\subsection{Models and Feature Engineering}

I compared six regression approaches:
\begin{enumerate}
  \item Linear Regression,
  \item RidgeCV,
  \item LassoCV,
  \item Elastic Net CV,
  \item XGBoost Regressor with randomized hyperparameter search,
  \item Huber Regressor as the robust baseline.
\end{enumerate}

Feature engineering was handled explicitly rather than implicitly. I generated polynomial and interaction features up to degree 3 to study the growth of the feature space and to support model selection. The raw 8 predictors expanded to 44 features at degree 2 and 164 features at degree 3. In the final modeling setup, degree-2 features were used for the linear and regularized models because they provided a more stable trade-off between expressiveness and numerical behavior than degree 3.

Recursive feature elimination was run on the polynomial feature space, and the selected set emphasized interaction-heavy terms involving \texttt{AveBedrms}, \texttt{AveOccup}, \texttt{Latitude}, and \texttt{Longitude}. This result suggests that simple main effects are not sufficient to explain the housing target well, and location-density interactions play an important role.

For the tree-based model, I used a randomized search over boosting hyperparameters. The best final XGBoost configuration used 350 trees, maximum depth 2, learning rate 0.15, subsample 1.0, column sample ratio 0.7, minimum child weight 3, \(\lambda=1.0\), and \(\alpha=0.0\). The Huber baseline was intentionally kept simpler, using degree-1 features on the raw target, because its main role in this assignment was to test whether a robust loss could mitigate outlier sensitivity and residual pathologies.

Model comparison used 5-fold cross-validation repeated 3 times, producing 15 paired fold-level measurements per model. XGBoost was the clear winner on every reported metric. Its advantage was not only numerical but also statistically consistent across folds. Paired tests on fold-level RMSE showed that XGBoost significantly outperformed Linear Regression (\(p=4.79\times10^{-18}\)), RidgeCV (\(p=2.24\times10^{-12}\)), LassoCV (\(p=2.57\times10^{-14}\)), Elastic Net (\(p=2.38\times10^{-14}\)), and Huber Regressor (\(p=6.62\times10^{-3}\)). The corresponding Wilcoxon signed-rank tests also favored XGBoost, with \(p=6.1\times10^{-5}\) in all pairwise comparisons reported by the pipeline.

After model selection, I evaluated the best cross-validated model and the robust Huber baseline once on the holdout test set. Table~\ref{tab:q1-holdout} confirms that the cross-validation ranking transferred to the final split: XGBoost achieved the best test performance, with RMSE \(=0.5052\) and \(R^2=0.8027\), while Huber remained substantially worse.

Residual diagnostics were also computed on the final holdout predictions. For XGBoost, the Breusch-Pagan test returned a p-value of \(1.67\times10^{-22}\), and the Jarque-Bera test returned \(p \approx 0\), indicating remaining heteroscedasticity and non-normal residuals. Huber did not solve these issues either; its Breusch-Pagan p-value was \(3.38\times10^{-132}\), and its Jarque-Bera p-value was again effectively zero. \subsection{Discussion}

The results show a clear bias-variance trade-off. Linear Regression had higher bias than the boosted tree model but still generalized reasonably well and remained much more stable than the regularized degree-2 variants. Ridge, Lasso, and Elastic Net all underperformed the unregularized linear baseline here, suggesting that the chosen polynomial expansion plus shrinkage introduced too much bias relative to the structure present in the data. In contrast, XGBoost captured useful non-linearities without the same feature-space explosion and therefore achieved the best predictive accuracy and the tightest fold-to-fold variance.

The robust regression experiment is informative precisely because it did \emph{not} fix the core problem. Although Huber is designed to reduce the influence of extreme observations, it still performed far worse than XGBoost and did not eliminate heteroscedasticity or non-normality in the residuals. This suggests that the residual violations are not caused only by a handful of extreme outliers; they are more likely tied to real non-linear structure, omitted interactions, and regional heterogeneity in the housing market.

Overall, the best-performing model in this experiment was the tree-based boosted regressor. It provided the strongest predictive performance, statistically significant improvements over all baselines, and the best final test-set results. The main limitation is interpretability: while the linear models are easier to explain coefficient-by-coefficient, they did not match the predictive quality of boosted trees. If I were extending this question further, I would keep XGBoost as the primary predictive model and pair it with model-agnostic interpretation tools such as SHAP to recover local and global explanations without sacrificing performance.
